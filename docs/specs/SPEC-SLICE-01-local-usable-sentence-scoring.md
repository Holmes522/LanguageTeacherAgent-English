## 1. 目标（一句话）

**在用户自己的 Windows 电脑上**：完成 DeepSeek 凭据配置后，输入一句英文，得到可用的评分反馈——分项得分、扣分证据、修改建议，并明确标注这不是考试成绩。

这条切片走通，产品第一次**真的能用**。它第一次把三层（界面 → Rust → Python）真正连起来，也是 T011 契约层与 T012 凭据存储第一次被真实使用。

## 2. 为什么第一条能力是句子评分

| 候选 | 结论 | 理由 |
|---|---|---|
| **句子评分** | **选它** | 量表**已定**（Q4 + 统一方案 §6.4 的 40/25/25/10）；零外部内容源；无授权问题；只需 DeepSeek |
| 查词 | 暂缓 | 开放许可词典的**具体来源与打包方式尚未决定**（Q1 只定了政策），牵出授权与分发问题 |
| 语法诊断 | 暂缓 | 需要语法知识库，来源同样未定 |
| 资料问答/RAG | 暂缓 | 需要导入 + 索引，是 M05/M06 的完整工作量 |

## 3. 范围（四步，按顺序）

1. **凭据**：设置界面录入 DeepSeek API key → 存入 OS 凭据存储；首次使用前显示一次 opt-in 说明（Q5），选择本地记录且可撤回。
2. **Sidecar 起得来**：`services/ai-core` 暴露 HTTP 服务，仅绑 `127.0.0.1` + 随机端口，鉴权 token 每次启动随机生成、只存内存（SPEC-M00 B-1/B-2）。
3. **Rust 代理**：注册第一个 Tauri command，转发到 Sidecar，并在 WebView→Rust 与 Sidecar→Rust 两条边界上调用 `src-tauri/src/contracts.rs` 已有的信封校验器。
   - **同时必须删掉 `main.rs` 上 `mod contracts;` 的 `#[allow(dead_code)]`**——该注解的移除条件就是"首个 IPC 命令落地"。
4. **能力**：`assessment.scoreSentence` —— 句子评分（100 分制：语法 40 / 词汇 25 / 自然度 25 / 拼写标点 10），每个扣分点带原文证据与可执行建议，附"AI 学习反馈，不是正式考试成绩"。

### 3.1 需要新增的契约（复用 T011 的既有机制）

- 在 `packages/contracts/schema/v1/` 新增业务 schema（句子评分请求/结果），并按 SPEC-M00 §5.2 的规定**追加**到既有 6 个来源之外。
- 跑 `pnpm contracts:generate` 重新生成 TS/Python 类型与 `schema-manifest.json`，并**扩展三方正反例**（至少覆盖：分项和 ≠ 总分、缺证据、分数越界、非正式考试的声明字段缺失）。
- `pnpm contracts:check` 必须保持 0；三方一致性条目数随之增加。

## 4. 非目标（本切片明确不做）

- 不做知识库、检索、引用（M04–M06）；不做 PDF/DOC/DOCX 导入；不做题库与错题本（M10/M11）。
- 不做 PyInstaller 打包 Sidecar，不做安装包与签名（T050）。开发期由 `uv run` 起 Sidecar 即可；**该风险不消失，分发给他人前必须回来做**。
- 不扩展 CI，不新增 Eval 门禁（按用户指令暂停投入）。
- 不做作文评分（先句子，后作文）。
- 不做多轮对话与历史管理。

## 5. 边界与红线（不得放宽）

- CSP / Tauri capability / ESLint 网络边界三层防护（SPEC-M00 §5.4）：WebView 仍不得直连外网，Sidecar 只由 Rust 代理访问。
- 密钥不进 Git、日志、SQLite、WebView 状态；只进 OS 凭据存储。
- 用户输入与模型输出都是不可信数据；模型输出不得直接进入 shell、SQL、HTML 或文件路径。
- 未 opt-in 时不得发起任何把内容送出本机的请求。
- 流式输出可取消；模型失败时给出可读错误，而不是整页崩。
- `main` 不直接推送；不合并 draft PR #1。

## 6. 验收标准（用户可在本机亲手验证）

| ID | 验收 | 怎么验 |
|---|---|---|
| AC-1 | 能录入并保存 key；重启应用后无需重输 | 录入 → 关闭 → 重开 → 直接可用 |
| AC-2 | key 不出现在仓库、日志、SQLite、WebView 状态 | `pnpm check:secrets` 为 0；界面无法读出完整 key；日志中检索不到 key 片段 |
| AC-3 | 未 opt-in 时不发出请求 | 清掉同意状态后操作，行为是提示而非发送 |
| AC-4 | 输入一句英文 → 得到 4 个分项 + 总分 + ≥1 条带原文证据的扣分点 + ≥1 条修改建议 | 手工输入若干句子观察 |
| AC-5 | 总分等于分项之和；输出是经 Pydantic 校验的 JSON | 契约测试；越界/缺项用例被拒 |
| AC-6 | 正确句子不被强行扣分或改写 | 人工抽查若干语法正确的句子 |
| AC-7 | 结果处明确显示"AI 学习反馈，不是正式考试成绩" | 肉眼确认 |
| AC-8 | 断网或无 key 时给出可理解的错误，界面不整体崩 | 拔网线 / 清空 key 各试一次 |

## 7. 本机验证命令

```powershell
pnpm install --frozen-lockfile
pnpm preflight:gate                 # 环境仍就绪
pnpm contracts:generate && pnpm contracts:check   # 新增 schema 后必须为 0
pnpm test:contracts                 # 三方一致性（条目数增加）
pnpm lint && pnpm typecheck && pnpm test && pnpm build
```
